# Границы статического анализа

`BSLParser` ищет объявления процедур и функций регулярными выражениями, собирает статические вызовы и ссылки на метаданные. `ImpactGraph` связывает только те вызовы, для которых в корпусе найдено совпадающее имя процедуры. Такой разбор полезен для поиска и первичного просмотра влияния, но не заменяет компилятор и запуск платформы 1С.

Независимая проверка выполнена BSL Language Server `1.0.7-DIRTY` в режиме `analyze -r json`. Инструмент обработал все 577 BSL-файлов и посчитал 3907 процедур и 3873 функции. Локальный парсер выделил 7342 сущности, на 438 меньше. Сводка лежит в [bsl-language-server-validation.json](../studies/oss-bsl-corpus-2026-08-10/bsl-language-server-validation.json).

Расхождение не исправляется подгонкой чисел. Оно показывает, что текущий парсер неполный. На этом запуске BSL Language Server также сообщил, что на машине нет контекста установленной платформы 1С. Поэтому результаты независимого анализа подтверждают обработку файлов, но не подтверждают выполнение конфигураций.

Особенно осторожно нужно трактовать:

- вызовы через переменные, `Выполнить`, reflection и другие динамические механизмы;
- строки запросов, собранные во время выполнения;
- совпадающие имена процедур в разных модулях;
- права, роли, подписки на события и конфигурационное окружение.
